# 内部混音开发与测试记录（2026-10-17）

这是第一阶段原型后的第二阶段整合：把 VB-CABLE 方案接入英雄识别、音乐库、片段、原有全局快捷键及浅色设置界面。相关功能已纳入 v1.2.0；正式使用与升级步骤见 [v1.2 使用说明](V1.2.md)。以下保留独立测试入口及验证过程，测试入口不包含在正式安装包中。

## 本机体验

1. 从第一版原型中退出或断开音频；不要同时运行正式版和测试版，避免两路混音或重复快捷键。
2. 双击桌面“LBGM 内部混音测试版”。首次启动自动复制正式版音乐库与键位到独立配置，正式库不被改写。
3. 向导选“内部混音 + VB-CABLE”，选择真实耳机、真实麦克风及 CABLE Input。点击“完成配置并进入”。需要麦克风权限；失败会提示并允许重试。
4. QQ 麦克风手动选 CABLE Output，扬声器选真实耳机。Windows 默认输入、输出也应保持真实设备，勿开启“侦听此设备”。如果检测到默认输出指向虚拟设备，设置面板会提醒，并提供打开 Windows 声音设置的入口；不会擅自修改默认设备。
5. 使用已有英雄映射或公共池。播放键、暂停键及 Ctrl+4 行为与 v1.1 一致，以界面显示为准。后台托盘运行仍传输麦克风。

每次启动不自动采集人声。可以点击“连接麦克风”，也可以按播放键同时建立混音并播放 BGM。暂停、切换片段或试听只暂停 BGM，不会关闭已经连接的麦克风。

## 音量与状态

- 音乐发送沿用固定的 `musicVolume`，不重新校准；耳机音乐沿用 `monitorVolume`。
- 内部人声增益独立保存（−24～+12 dB），初始 0 dB；不会套用 Voicemeeter 的 +12 dB。历史处理参数不自动套用；内部默认全频段立体声。
- 人声不参与音乐的弱网或响度处理。混合总线有峰值保护；不能修复麦克风采集前已经出现的失真。
- “麦克风静音”只静音人声，BGM 仍发送；监听音量 0 只关闭耳机里的音乐。
- 耳机监听/试听只播放音频文件，不连接真实麦克风或 CABLE Output。
- 电平条展示人声、音乐和总混合电平。缓冲延迟仅为本地引擎信息，不是 QQ 端到端延迟。
- “测试虚拟输出”向混合总线发送约 1 秒轻测试音，不回听到耳机；“停止测试”不关闭麦克风。

点击“断开全部音频”或真正退出应用后，QQ 的 CABLE Output 不再收到本应用人声，请在 QQ 切回真实麦克风。内部方案退出会显示提醒；最小化到托盘不停止采集。设备丢失、绑定失败或休眠中断会停止混音并提示，不回退到默认设备。

## 单一音频方案与配置隔离

已按用户确认移除 Voicemeeter 兼容方案、官方安装入口、外部路由配置和增益守护。应用仅使用内部混音 + VB-CABLE；“配置音频设备”可重新选择真实麦克风、耳机及 CABLE。旧配置中的历史字段只作为迁移数据保留，不会恢复旧路由。

- 正式配置：`%APPDATA%\champion-soundboard\settings.json`
- 第一版原型：`%APPDATA%\lbgm-audio-prototype\prototype-settings.json`
- 整合测试版：`%APPDATA%\lbgm-internal-preview\settings.json`

首次复制后各自独立；测试版之后新增或修改的音乐不会自动写回正式版。首次配置内部方案还会保存 `settings.before-internal-audio.json`，不覆盖已有备份。未添加开机自启动，测试入口曾与“英雄音乐台”指向同一构建；重复入口已清理，日常保留“英雄音乐台”。开发者仍可按下述脚本创建独立测试入口。

源码启动测试版：`npm start -- --audio-preview`。不要把测试版截图或本机配置当作新版已发布的证明。

2026-10-17 本机测试入口更新为独立打包目录 `release/internal-audio-preview/win-unpacked/`，启动参数仍为 `--audio-preview`，沿用同一份测试版配置；测试配置与正式安装配置仍然隔离。窗口标题显示“测试版”，标题提示中有构建日期。退出旧测试版后再打开桌面入口，才能加载新构建。

开发时源码改动不会自动更新打包副本。重新打包与更新测试快捷方式：

```powershell
.\node_modules\.bin\electron-builder.cmd --win --dir '--config.directories.output=release/internal-audio-preview'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/create-audio-preview-shortcut.ps1 -Packaged
```

不传 `-Packaged` 时创建的是源码测试入口；检查快捷方式实际目标，避免测试旧副本。

## 验证范围

- 23 项单元测试通过，覆盖旧库迁移、独立音量/处理状态、预览配置隔离、移除旧安装/路由入口并拒绝旧方案、峰值保护及设备筛选。补充真实 MediaDeviceInfo 原型 getter 用例，防止整理设备列表时丢失设备 ID；整合界面测试也使用该对象结构。
- 原有 61 项界面回归检查：首次向导、英雄/昵称、公共池、映射、真实快捷键捕获、双路播放、片段及提示。
- 54 项整合检查：使用合成麦克风、真实 Chromium 音频图和静音输出；确认混音、暂停人声连续、片段结束、三槽位、Ctrl+4、静音、音量、断开重连、设备消失、授权/输出失败、延迟取消、向导重试、旧库迁移、默认设备警告、刷新保留选择、编号变化后的恢复以及重启后的配置保留。
- 30 轮快速断开重连均释放采集；模拟 AudioContext 暂停后可显式重新连接。此检查不是 30 分钟耐久测试，也不等同于真实 Windows 休眠/USB 拔插测试。
- 第一阶段实际 CABLE 回路已经检测低、中、高频，用户也确认 QQ 通话正常。用户已反馈整合版功能测试正常；后续构建仍需按实际使用复核，自动检查不能代替远端听感验证。

运行检查：`npm test`、`npm run test:renderer`、`npm run test:internal`。整合测试使用模拟设备及独立临时目录，不采集真实麦克风，不改变系统路由。

最新构建与保护范围见 [2026-10-17 验证记录](QA-internal-audio-2026-10-17.md)。
