# LBGM 内部混音原型（第一阶段）

这是独立实验入口，不替代 v1.1，不注册正式版全局快捷键，不接入英雄检测，也不修改 Windows 默认设备或 Voicemeeter 路由。

## 启动

双击本目录 `launch.cmd`，或在项目目录执行：

```powershell
.\node_modules\electron\dist\electron.exe .\prototype\audio-mixer\main.cjs
```

无新增 npm 依赖。需要 [VB-CABLE](https://vb-audio.com/Cable/) 驱动：管理员安装后重启。不必卸载 Voicemeeter。原型拒绝选择 Voicemeeter Input 作为实验输出，避免与其现有麦克风路径产生双重混音。

## QQ 实验

1. 点击“授权 / 刷新设备”。选择真实麦克风、CABLE Input、物理耳机。
2. 点击“连接并开始传输麦克风”，正常说话检查麦克风和混合电平。
3. QQ 麦克风手动改为 CABLE Output；先请对方确认纯人声正常。
4. 导入音频，设置起止秒数，播放并确认对方能同时听到人声和音乐。
5. 暂停、续播、切换三个槽位、Ctrl+4 重播时继续说话，检查人声不中断。
6. 麦克风增益从 0 dB 开始，可增加至 +12 dB；发送音乐默认 13%，耳机监听独立。关闭耳机音乐仅需将监听调为 0。
7. 音乐暂停后保持至少 30～60 分钟通话，测试最小化窗口、切换应用；随后检查 USB 拔插和休眠恢复，出现提示后重新连接。
8. 检查游戏/B站/网易云仍走耳机且不被对方听到。不要把 CABLE 设为系统默认，不开“侦听此设备”。

原型快捷键**仅窗口获得焦点且未编辑输入框时有效**：Shift+1/2/3 播放，Ctrl+A 暂停/继续，Ctrl+4 从当前片段起点重播。第一阶段不验证英雄检测或游戏全局按键。

最小化窗口可以持续混音；真正关闭或点击“断开全部音频”会停止麦克风传输。此时 QQ 必须切回真实麦克风或原有 Voicemeeter B1。原型不会自动更改 QQ 设置。

## 技术边界

- 麦克风通过 getUserMedia 采集，默认关闭软件回声消除、降噪和自动增益，适合戴耳机实验；使用扬声器时仍可能产生声学回声。
- 同一 Web Audio 图混合麦克风和 BGM，直接绑定 CABLE Input；AudioWorklet 做峰值保护（约 −1 dBFS）。该保护不能修复麦克风或音源已经发生的失真。
- 本地监听是单独的 BGM 路径，不连接麦克风。音乐发送、麦克风增益及监听音量独立；本阶段不接入弱网模式或响度稳定器。
- 48 kHz、交互延迟提示是请求，不保证完整通话延迟。界面报告的基础/输出延迟不能相加后当成 QQ 端到端延迟。
- 不录音、不保存人声；独立配置仅写 `%APPDATA%\lbgm-audio-prototype\prototype-settings.json`，保存设备选择、音量和测试音频路径。启动不自动采集麦克风。
- 设备丢失不回退系统默认。诊断复制包含设备标识，分享前检查隐私信息。
- 本阶段未发布至 GitHub Release，也没有修改正式版安装包。

## 已完成验证（2026-10-13）

- 15 项单元测试通过（含原有正式版测试与原型设备、片段、峰值保护测试）。
- 27 项真实 Chromium 音频图与界面检查通过：使用合成麦克风和测试 WAV，验证同时混音、暂停/片段结束保留人声、重播、三路音量、静音、断开/重新连接、设备消失、输出失败和异步取消清理。
- 测试路由使用静音 sink 和模拟设备，不采集真实麦克风，不修改系统音频配置；结果不等同于完成 QQ 联调。
- 本机暂未检测到 VB-CABLE，因此实际虚拟设备输出、QQ 远端听感及 30～60 分钟耐久测试待用户实验。
